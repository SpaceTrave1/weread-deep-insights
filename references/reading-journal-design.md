# 阅读手记：完整报告与双视图

## 内容架构

| 模块 | 保留／整合内容 |
| --- | --- |
| 阅读总览 | 官方时间、天数、读过／读完、导入正文数量、分析范围、其他模块入口 |
| 阅读地图 | 年度时间／天数切换、分类、书籍时长、作者加权线索、书架与官方完读比例 |
| 笔记与表达 | 点评／划线区别、目录笔记排名、点评年份分布、全部导入正文的类型／年份／文本检索及分页 |
| 我的思考 | 已有模型语义结论、反向证据、规则主题与表达线索；同一问题档案的主题／时间视图、完整点评、书中背景、版本时间、反馈与重新核对提醒 |
| 阅读启发 | 原报告的可选练习、集中度与覆盖提醒、预设书单推荐 |

“价值观／焦虑”“信息茧房”“严格诊断”和人格式评分不作为新的导航名称。原有可核对统计、词汇线索及证据保留，集中度／完成比例只作为描述指标。传统 Markdown 与旧渲染器保持兼容，新的 Markdown 合并基础报告与演化档案；新 HTML 不把旧能力评分作为视觉主轴。

## 视觉方向与品质目标

延续纸色 `#f5f2ec`、深绿 `#254d41` 和编辑式排版。使用系统宋体呈现书刊标题和原文，系统无衬线字体呈现控件、日期与数据，Georgia 呈现数字。固定侧边目录、轻边线、少量绿色强调、数据图表和原创 CSS 封面共同形成统一设计。移动端切换为固定顶部目录，保留相同模块与阅读路径。

Awwwards 官方评价包含设计、可用性、创造性和内容，本项目把这些作为设计检查方向，而非自行赋予评审分数。[Awwwards evaluation](https://www.awwwards.com/about-evaluation/)

Webby 官方网站评价还关注结构导航、功能、交互、创新和整体体验。因此验收应覆盖深入阅读原文、筛选、时间视图和反馈，而不只检查首屏截图。[Webby judging criteria](https://www.webbyawards.com/judging-criteria/)

FWA 作为创意与完成度的参考目标；没有引用未核实的 FWA 分值或门槛。本项目没有参赛、外部评审或获奖认证。自查不能证明一定达到任何奖项的获奖标准。

## 验收与改进记录

1. 第一轮：恢复完整报告结构，检查桌面总览、阅读地图和主题视图；把正文检索和数据快照标注纳入页面。
2. 第二轮：检查手机阅读宽度、原文展开、关系筛选和双视图；加深低对比度辅助文字，为触控导航增加最小高度，并增加手机可见的数据范围入口。
3. 第三轮：复核边界状态、较小屏幕、主题至对应时间档案的跳转、补充档案自动展开、键盘标签切换、反馈协议、已有测试及输入绑定。

实际浏览器尺寸、操作结果、运行错误、截图和性能读数存放在私有输出目录的 QA 记录中，避免把个人数据或截图提交到仓库。合成测试与实际个人网页视觉检查分别记录，不把个人材料用于测试样本，也不将结构测试当作模型语义质量验证。

检查内容：

- 完整报告的五个模块可到达，主题／时间视图共用同一问题档案；首屏保留分析范围入口。
- 全部导入正文在本地可检索，长原文、无结果、未知日期、缺少语义／演化结果有明确状态。
- 个人点评覆盖计数不包含划线；分片重新组合为完整笔记，不把片段当独立笔记。
- 区分成功、空数据、失败、未请求和未知；没有数据时不自动显示有效零值。非法完成比例不显示为百分比结论。
- 核对桌面、平板和手机布局，没有内容造成的横向页面溢出；可见常规正文和控件文字检查对比度。
- 键盘可以切换标签与使用原生控件，有焦点提示和跳过导航入口；动画尊重 `prefers-reduced-motion`。
- HTML 对用户和模型文本转义，JSON 脚本块不能被 `</script>` 提前终止；动态笔记用 `textContent` 写入。
- 单文件无外部图片、字体、脚本、遥测或主动网络请求；不访问 `.env`、账号凭据或数据库写操作。
- 反馈导出与现有三字段导入协议一致；带版本的轨迹 ID 决定所审阅解释，不继承旧反馈为新确认。
- 旧 CLI、协议版本、标准库依赖及传统渲染不受新入口影响。

浏览器预览不等于跨浏览器、真实移动设备、屏幕阅读器或打印成品验收。明确记录未执行的检查，不称其通过。

本轮验证结果：161 项合成／模拟测试通过，其中新增 14 项整合网页回归测试；Python 编译与 JavaScript 语法检查通过。320、390、768、1280 像素四种视口分别检查六个页面（五个模块加覆盖说明），24 组检查均未发现页面横向溢出或可见常规文字低于 4.5 的对比度。另检查时间视图、笔记筛选与分页、无结果、键盘标签、补充档案跳转、手机覆盖入口和反馈必填提示，浏览器控制台未记录运行错误。对比度检查基于当前浏览器计算样式，不等于完整无障碍审计。

## 兼容性与范围

新增 `render_journal.py`、独立渲染模块和内嵌 CSS/JS，不修改原有采集、分析或生成器默认行为。浏览器使用现代标准 JavaScript；无 JavaScript 时静态报告及证据仍可阅读，笔记检索、分页和反馈导出需要 JavaScript。打印样式展示多个模块，笔记库仅包含当前分页呈现的原文，不声称打印了全部笔记。

所有输入都来自同一账号的用户授权材料。历史与演化报告必须属于同一 dataset，语义结果必须绑定其原始证据包；新统计覆盖与所标注历史覆盖必须一致。不同快照仍保留各自日期，不将旧分类或旧模型结论称为重新采集／分析。

本次没有重新请求微信读书数据，没有重跑语义分析，也没有进行独立模型准确率评测。真正的完整历史编辑版本、跨账号融合、云端反馈持久化和全局知识图谱不在此次范围。
