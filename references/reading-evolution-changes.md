# 阅读观点演化实施记录

研发只使用合成数据和模拟接口，不读取真实笔记或凭证，不调用微信读书或模型 API。语义质量目标需要独立人工评测，不能从工程测试通过推导。

## 阶段一：历史证据

- 原采集丢弃外层 `reviewId`，划线缺少源标识和修改时间；保留接口实际提供的字段，缺失时明确为临时身份。
- 新增标准库 SQLite 历史库：数据集隔离、笔记实体、内容版本、采集观察、覆盖状态及反馈日志。内容编辑不会增加独立笔记数；书名更正不会制造内容版本。
- 创建、修改、观察时间分开；编辑和恢复旧内容不重定年到原创建时间。第一批历史内容的原始版本未知。
- 失败、空数据和本次未取得均不推断删除；冲突源版本和非法采集时间事务回滚。清理只处理指定历史库，导出、报告、备份需另行清理。
- 先写 14 项历史契约测试，确认模块不存在时失败，再实现；增加恢复旧版本测试后，全套 98 项测试通过。原有 83 项测试基线通过。
- 保留旧分析包 1.0 和旧 CLI 行为；历史模块只在新入口使用。Gateway 版本从此前待提交的 1.0.3 更新为 1.0.4。

## 阶段二：观点与候选协议

- 先建立核心合成契约测试，再实现独立演化协议；原语义协议 1.0 未改动。
- 提取观点的问题、对象、条件、理由和主体；只有完整抽取的个人点评参与确定变化。按主题、相邻节点和跨时锚点产生有界候选，并提供实际原文反证片段。
- 两端引用、不同实体、身份、时间及比较条件均受校验；不满足时保留张力或弃答。未收到宿主结果不计为成功或成功但为空。
- 新增源时间矛盾/未来时间、同一笔记编辑不增加观点数、长文本无损分片和未收到比较结果测试。核心演化 18 项、历史 16 项分别通过；未进行真实模型语义评测。
- SQLite schema 1.1 从本阶段 1.0 追加缓存及问题索引；旧代码不支持读取新历史库。实体版本与分片分离；模型声明、提示及输入变化使缓存不同，命中后重新验证。

## 阶段三：反馈、报告与验收入口

- 接入独立可选 `--analysis-focus evolution`；旧 CLI 默认行为、画像导入协议及报告文件名保持不变。新 `evolution.py` 负责离线准备、导入、渲染、反馈、导出与清理，不读取环境文件或调用网络。
- 问题档案按时间组织多条独立点评，保留中间节点及关系；首页最多 5 个问题档案，其余可展开。显示完整点评、时间来源、章节缺失、精确引文、反证搜索范围、采集/抽取/比较覆盖。
- 反馈追加保存，绑定实体、内容版本及当时的模型解释。来源或解释改变不会继承旧确认，相关用户解释供下轮比较使用。只有完成抽取的本人表达进入持久问题索引。
- 数据为空、未收到模型结果、弃答、部分范围和选中范围处理完成分别呈现。相同表达不能包装成修正/反转；时间不可信或比较条件不满足时只保留张力。
- 固定三节点演示来自虚构点评和手工编写关系。合成语义评测共 60 个模板场景（开发/留出各 30），标准答案不进入请求。独立人工复核、至少 20 个修正/反转候选、样本支持率 ≥90% 为初始门槛，并报告漏检、样本量和 Wilson 区间。未复核的留出表实测为 `semantic_pass=false`、准确率 `null`；未声称真实模型达标。
- 新增合成回归快照；历史版本导出遮盖联系人，清理同时覆盖缓存、反馈与索引。未知数据库版本在任何 schema 变更前拒绝。
- 验证中发现新增测试的 SQLite 上下文未关闭连接，Windows 临时目录清理失败；改用显式关闭后全套 147 项测试通过。该记录针对测试连接，未将失败一轮称为通过。
- 兼容性风险：新历史库仅向前迁移到 1.1；旧画像包不能替代带源 ID 的历史采集数据；演化与画像共用报告文件名，建议分目录保存。历史库不加密，自定义输出需自行确认 Git 忽略。真正 API 增量同步、旧内容恢复及独立语义验收尚未完成。
