# v0.2 大模型增强实施说明

实施日期：2026-10-09。开发分支：`feature/llm-evidence-analysis`，基于可靠性阶段提交 `d2a082a40fedac7612c3bd5789445da7c1898047`。本次提供宿主 Skill 与显式 API 的共同分析协议、执行通路和离线验证基础，不声称已经验证真实模型的分析准确率。

## 问题与修改

| 原有限制/可靠性风险 | 实施方式 | 验证 |
| --- | --- | --- |
| 关键词词表限制新主题、否定、反讽和转述分析 | Python 保留计数；版本化提示让模型解释语义，允许任意主题名称；旧规则结果独立展示 | 任意园艺主题协议验证；10 个合成语义场景和人工准则，尚未评分 |
| 宿主 Skill 无结构化分析通路，额外 API 成为门槛 | 导出字段白名单输入包，生成有界请求，宿主 JSON 校验导入；API 使用同一协议 | 离线宿主导出/导入往返，禁止重新采集或读取密钥 |
| 模型可能改写统计、编造引文或把划线当立场 | 摘要绑定、严格字段、引用 ID/原文子串、个人点评门槛与弃答；官方指标只从本地基线读取 | 伪引文、伪 ID、额外统计、未知字段、仅划线、独立跨书和时间门槛 |
| 全局画像和时间变化被少量片段支撑 | 片段/样本范围；独立笔记数量、跨书、点评和时间条件 | 单书/薄数据拒绝画像，未知日期拒绝变化，有日期场景可通过结构门槛 |
| 长数据容易静默截断并暗示完整分析 | 全笔记轮选后无损切片、按书提取、带原文综合；选中/声明/完整笔记数分开呈现 | 分块无重复遗漏、每块字符上限、综合原文与部分范围、切片不膨胀笔记覆盖 |
| 失败重试成本与数据传送不透明 | 显式上传开关、专用密钥变量、HTTPS/回环限制、禁止重定向、调用总上限、超时和用量记录 | 两种协议模拟请求、预算耗尽、截断/异常响应、无授权不读取密钥 |
| 重复分析浪费调用；快照变化时缓存引用可能过期 | 按完整请求配置缓存，未变化的局部提取可增量复用并重新绑定/校验 | 缓存命中、坏缓存重试、变更整体统计后提取复用 |
| 部分模型失败导致丢失全部结果或伪装完成 | 保留有效局部观察，综合失败标明警告；全部失败输出本地规则回退和非零退出码 | 调用限制后局部保留、失败报告保留尝试计数、无效宿主结果回退 |
| 自由模型文本可能注入 HTML/Markdown | 统一逃逸模型文本、引用、来源与告警；记录字段验证 | 合成脚本和链接注入、非法计数字段被拒绝 |
| 导入坏包或局部 ID 太长导致新通路不稳定 | 包摘要/片段完整性/基线形状检查；合并局部 ID 使用短摘要；先渲染两种格式再写 | 重算摘要的损坏包、缺片、坏嵌套结构、最长合法局部 ID |

## 兼容性和剩余限制

- 保持 Python 标准库依赖、原 CLI 参数及默认行为、Markdown/HTML 输出名和直接脚本/模块运行方式。没有参数时不调用模型；新增功能全部通过可选参数启用。保留可靠性阶段的 Gateway 版本，不修改 `main`。
- 报告内部增加 `llmAnalysis`；开启增强后加入来源、证据、局限、模型覆盖与用量段落。旧规则段落保留，依赖报告原文的外部程序需要适配。
- 字段、引用和数量门槛只能校验结构与可追溯性；无法认证模型归纳、反讽识别或反证审查是否正确。不存在经过实测的质量提升比例。
- 当前是按书提取加一次有界综合；最终输入和输出预算可能限制跨书全量归纳。会明确输出部分覆盖或局部观察，不保证所有选中内容都出现在最终综合中。
- 模型服务字段支持、真实账户权限和端到端可用性未做真实集成验证。JSON mode 不保证输出有效，失败仍走校验与回退。
- 联系人遮盖不等于匿名化；输入包、缓存和报告仍是私有阅读数据。上传授权独立于微信读书采集授权，实际留存以目标服务政策为准。
- 字符预算、尝试上限和报告用量不等于金额上限；失败费用和未返回用量可能缺失。需要服务端预算配合。

使用步骤与完整协议见 [大模型分析指南](llm-analysis.md)。后续应在仅使用合成/脱敏且获得上传授权的数据上完成真实模型评测，并人工审阅证据支持率、反证遗漏和新主题质量，再决定是否调整默认工作方式。
